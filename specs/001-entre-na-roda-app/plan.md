# Implementation Plan: Entre na Roda Web App

**Branch**: `001-entre-na-roda-app` | **Date**: 2026-09-29 | **Spec**: [specs/001-entre-na-roda-app/spec.md](../specs/001-entre-na-roda-app/spec.md)

**Input**: Feature specification from `/specs/001-entre-na-roda-app/spec.md` and technical decisions from `docs/plan-entrada.md`.

## Summary

Implementação da aplicação web educacional estática "Entre na Roda" para alunos do 3º ao 5º ano (8 a 10 anos) sobre a unidade temática de Lutas (Capoeira), com base na habilidade BNCC EF35EF15. A aplicação utiliza HTML5, CSS3 e JavaScript puro (Vanilla JS), sem frameworks, sem etapa de build e sem dependências externas, contendo tela inicial, Etapa 1 (8 situações "Luta ou briga?"), Etapa 2 (5 desafios "Conheça a roda"), Tela final com resumo e seção "Vale rever", e página de orientação para o professor. Todo o conteúdo pedagógico é estático e embutido via `docs/conteudo-pedagogico.md`.

## Technical Context

**Language/Version**: HTML5, CSS3, JavaScript (ES6+)

**Primary Dependencies**: Nenhuma (Vanilla JS puro, sem bibliotecas externas)

**Storage**: Memória de sessão do navegador (`sessionStorage` / estado em memória)

**Testing**: Roteiro de testes manual em `docs/roteiro-testes.md` cobrindo viewports de 360px, 768px, 1280px e dispositivo móvel real.

**Target Platform**: Navegadores web modernos (Chrome, Firefox, Safari, Edge) em celulares, tablets e computadores, publicados via GitHub Pages.

**Project Type**: Web application estática educacional

**Performance Goals**: Carregamento instantâneo (< 1s) em conexões móveis comuns.

**Constraints**: Sem servidor, sem banco de dados, sem login, sem dependências externas, sem rolagem horizontal em larguras de 360px a 1440px, conformidade WCAG 2.1 AA.

**Scale/Scope**: 1 arquivo HTML principal (`index.html`), 1 página de professor (`professor.html`), estilos em `css/estilo.css`, dados em `js/conteudo.js`, lógica em `js/app.js`, arquivo `.nojekyll` e roteiro de testes em `docs/roteiro-testes.md`.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Adequação pedagógica (Princípio I)**: ATENDE. Foco na habilidade EF35EF15, feedbacks explicativos, pistas antes de revelar a resposta, sem ranking, cronômetro ou vidas.
- **Respeito cultural e precisão histórica (Princípio II)**: ATENDE. Capoeira como resistência cultural negra, textos pedagógicos oficiais extraídos diretamente de `docs/conteudo-pedagogico.md`.
- **Clareza da interface para crianças (Princípio III)**: ATENDE. Objetivo único por tela, frases curtas, síntese de voz opcional (Web Speech API).
- **Acessibilidade (Princípio IV)**: ATENDE. Contraste WCAG 2.1 AA, alvos de toque >= 44x44px, fonte >= 18px, sem arrastar e soltar, sem dependência exclusiva de cor.
- **Simplicidade e escopo controlado (Princípio V)**: ATENDE. Site estático sem build, sem servidor, sem dados pessoais, sem dependências externas.
- **Verificabilidade (Princípio VI)**: ATENDE. Critérios observáveis e roteiro de testes manual estruturado para três viewports.
